# Undead Survivor 开发记录

## 跳跃河道与波次生存（2026-09-04，当前规则）

本节及 README 为当前规则；下方其他章节是历史记录。

- 场地中间增加弯曲河道，宽约 2.5 m，河床低于两岸；两座木桥位于 x=-10 和 x=10。地面网格真正沿河道切开，水面、河岸、桥面和导航共用 `terrain.ts` 数据。
- 空格单次跳跃，初速度 8.4 m/s，重力 18 m/s²，最高约 1.96 m、腾空约 0.93 s，前跳约 3.92 m。腾空期间始终按当前视角正前方移动，鼠标转动可改变轨迹，WASD 完全忽略并在落地后恢复；空中不能连跳。暂停冻结高度与速度，恢复后继续，不重置落地状态。
- 玩家可以在空中跨水，直接走入河流或落地位置在水中立即失败。桥面可安全通行。练习模式也判落水失败，但不写榜。
- 僵尸不能跳跃；共享网格寻路将河道视为障碍，只走桥。河道用保守的窄矩形分段表示，实际移动用连续线段碰撞检测，避免桥角穿水；玩家空中经过河道时，导航目标投影到可达河岸。
- 第 n 波固定生成 `9 + 6 × (n - 1)` 只，速度 `1.4 + 0.15 × (n - 1)` m/s，生成速率 `min(10, 1 + 0.2 × (n - 1))` 只/s。全部生成并清掉存活僵尸后休整 5 s，然后开下一波。尸体不阻止清波。
- 北、东六个固定入口与前方/8 m 限制保留；入口暂不可用时等待，不丢弃波次配额、不累积突发补刷。暂停、后台和未锁鼠标时，跳跃、生成、波间倒计时与游玩时间均冻结。
- 生命 100、攻击伤害 10 和护甲规则保留。武器库现有十款：原六款动画枪，以及自制的消防斧、穿透喷火枪、自动霰弹枪和重机枪。所有武器支持不改变弹道的右键抬枪动画。足够高的跳跃可躲避挥击，已生成的僵尸始终追击玩家。
- HUD 显示当前波、剩余配额及活怪总数、已守住波数、波间倒计时和跳跃提示。失败按已清完波数计分；同波数比较击杀，再比较时长。新键 `undead-survivor.leaderboard.waves-v1`，旧时间榜数据保留但不混排。
- 开发端口 5176，测试独占 5177；浏览器测试单 worker，不复用已有服务器。新增验证涵盖跨河、两桥寻路、低帧率跳跃、落水、完整清波、休整暂停、升波和波次入榜。
- 实际浏览器截图：`screenshots/river-crossing.png`、`screenshots/waves-result.png`。本次只交付源码和网页版，不重新打包 portable EXE。

## 障碍寻路与突破者特写（2026-09-04，仅源码/网页版）

本节描述最新行为，取代下文历史记录中的可见圆弧、失败定格和无障碍直线追击。

- 移除黄色/红色防线、刻度和精确距离提示，保留接近哨塔的文字警告。内部失败半径仍为 8 米，成绩在首次突破时冻结。
- 加入独立的 `breaching` 阶段：镜头在前 0.8 秒推进并转向实际突破者，随后展示伸臂扑击；降低其他僵尸亮度，增加突破者受光，同时播放低沉失败音效。取景先检查场景射线，避开哨塔护栏、立柱与平台对镜头路径和扑击头胸位置的遮挡。共 2 秒后自动结算和显示排行榜。战斗中的有限视角不变，重开恢复相机位置与视野。
- 场景模型与导航共用实体占地，包括检查站、车辆、混凝土路障、整段围栏、门柱、树干和岩石，共 186 个静态障碍。树冠、草和可从下方通过的高架横杆不封路。以轴对齐包围盒表示地面占地，再扩张 0.95 米，给僵尸伸出的手臂留出空间。
- 用 0.65 米栅格一次建立反向 Dijkstra 最短路场，所有僵尸共享。通路畅通时直行，遇障碍才沿场寻路并用视线捷径减少折线。连续碰撞校验实际移动线段，拥挤避让不得穿过实体；无可达路径时停止，出生点落入障碍时投影到附近可达区域。
- 保留八区域刷新、护甲比例、六枪数值与本机排行榜。此前基于无障碍直线路程的时长模拟不包含此次绕行，不能作为新版局长结论。障碍目前为静态实体，不支持破坏或动态移动。
- 不重新打包便携 EXE。

## 项目定位

一款固定哨位的 3D 生存射击游戏。玩家驻守哨塔，武器覆盖眼前的防区，镜头只能在固定朝向的小范围内以较强阻尼转动。后续游戏张力来自前方威胁、装填时机与防线管理，而不是自由移动和大范围转身。

美术参考《未转变者》的方块化轮廓、低面数几何和简洁色块，所有模型均为本项目原创程序化模型，不导入该游戏资产。首个场景使用松林、路障、检查站、巡逻车、哨塔护栏构成明确空间层次。

## M0 交付范围（0.1.0）

1. 建立可运行、可构建、可继续扩展的项目。
2. 第一人称右手持枪，手臂与枪械为真实 3D 几何。
3. 鼠标自由准星；枪口指向鼠标对应的世界位置。
4. 镜头有可感知的小幅阻尼跟随，但朝向绝不无限累积。
5. 左键射击，包含火光、枪口照明、曳光、抛壳、后坐平移、命中碎屑与枪声。
6. 用可复位的人形靶闭合验收流程；包含弹药、换弹、暂停、设置与错误提示。
7. 立项文档、操作说明、自动化测试和实际画面证据。

M0 阶段先完成持枪、瞄准和镜头规则，敌人追击在 M1 加入。

## M1 交付范围（0.2.0）

1. 人形练习靶替换为原创方块僵尸，包含绿色皮肤、破旧衣服、前伸手臂与行走动画。
2. 主菜单提供练习与正式模式。练习僵尸静止、击倒复位；正式僵尸被击杀后回收。
3. 正式模式固定为原困难难度，移除三档难度选择；保留练习和正式模式切换。
4. 前方防区设置八个刷新区域：远端公路、左右路肩、检查站通道、站前空地、围栏通路和左右林地。每轮洗牌后依次使用，沿各自路径接近；窄窗口跳过不可见固定入口。
5. 用刷新率积分累计生成数量，封顶每秒 10 只；小步推进移动，任何活僵尸到达 8 米失败半径即结束。
6. 有效坚守计时在暂停、设置和失焦时冻结，失败后停止移动、刷新、开火和计时。
7. 结算提供坚守时长、击杀、射击统计、重试与返回主菜单；展示本机困难榜前 10 名，旧简单、普通纪录保留但不展示。
8. 僵尸共用一个实例化模型，先按个体包围盒筛选射线，再检测实际身体方块，保留头部和身体伤害差异。

正式模式是连续生存，无固定波次和胜利终点。排行榜是当前浏览器的本地纪录，不做账号与联网竞争。数值和操作详见 README。

## 0.3.0 护甲扩展

2026-09-04 试玩反馈完善：护甲拆为 100 本体 + 100 路障 / 300 铁桶，优先承受伤害，脱落后变为普通僵尸且立即移除护具碰撞，总耐久不变。路锥与铁桶各有受击/脱落声音，脱落模型最多 24 件，通过单次实例绘制飞起、旋转和回收。正式模式显示与判定共用半径的防线圆弧，失败记录首个越线 ID，定格指示并支持结算后复看。结算比较写入前的个人最佳；总音量和静音独立保存。

普通、路障和铁桶生命为 100、200、400。简单只出普通；普通从开局按 3 普通、1 路障循环；困难每累计 2 只路障追加 1 只铁桶，完整循环为 6 普通、2 路障、1 铁桶。没有 30 秒门槛。路锥和铁桶增加在原有尸群实例模型中，护具参与头部命中。新旧难度规则的排行榜分开保存，当前为 armor-v3，旧纪录保留。

单局目标为多数玩家自然坚守 1～3 分钟。本轮用实际战斗逻辑进行 720 局操作模型评估，明确区分操作假设、理想机器人与真人数据；结果和约束见 `BALANCE.md`。

## 圆弧突破与轻微避让（历史方案，已被下述直线追击替代）

每个出生个体获得独立的 8 米圆弧突破点，最大覆盖基准朝向左右各 35°，窄屏缩小范围。原有入口和路径点保留；通过入口通道后，僵尸向不同的突破点扇形散开。空间网格仅查询附近活僵尸，距离小于 1.35 米时加入平滑横向避让，总速度不增加，横向避让速度上限 0.32 米/秒且不超过移速的 20%，最后 2 米逐渐减弱。身体朝向跟随实际运动方向，尸体不参与避让。

失败检测使用实际移动线段与 8 米圆的首个交点，包含同一帧经过路径点的情况；全队在最早越线时刻冻结。练习、护甲血量、出怪比例、难度增长及排行榜存储键不变。

| 项目 | 规则 |
| --- | --- |
| 坐标 | 世界前方为 -Z；相机位于 (0, 4.8, 9) |
| 基准俯角 | -0.105 rad，略俯视公路 |
| 水平转动 | 基准方向附近 ±4° |
| 垂直转动 | 基准方向附近 ±2.5° |

| 武器朝向 | 本地 -Z 对准世界瞄准点；镜头和枪械分别更新 |

| 弹道 | Hitscan；准星求点后从枪口复核遮挡 |

| 失败 | 正式模式活僵尸到达玩家地面位置的 8 米半径 |
| 刷新上限 | 10 只/秒；实例容量 256（含尸体），满额时跳过刷新 |

近距离护栏可能挡住枪口，此时命中实际遮挡物；不允许为了对齐准星而穿过墙体。常态持枪缩小并下移，装填时侧倾，左手抽匣、插匣、压紧，空仓时释放枪机；肩部固定、双段手臂随腕部求解。动画与进度条由同一有效换弹进度驱动，期间不能开火。

## 技术方案

采用 React + TypeScript + Vite + Three.js。选择浏览器原型是为了快速试玩、方便迭代操控，无需先安装游戏编辑器或桌面运行时。

- React 只处理菜单、设置和低频 HUD 刷新；帧循环由 Three.js 类管理。
- 纯函数实现视角约束和枪口四元数，独立状态机处理武器装填与冷却。
- 场景、枪械、音频分离，后续可以逐模块替换正式资源。
- 音效与 BGM 共用总音量，音乐独立低增益并在战斗时自动压低。BGM 单实例循环，仅游玩时播放；死亡低吼三种缓存变化，最多三声重叠。所有音频原创程序合成，离线可用。
- 第一阶段无需完整物理引擎。射线测试完成命中与遮挡，轻量粒子模拟完成碎屑和弹壳。
- 场景仅在可见且必要时绘制，限制帧率、像素总量、阴影更新频率和粒子上限。
- 开发模式提供只读 `window.__undeadTower.snapshot()` 以便验收；生产构建不暴露该接口。

## 项目风险与应对

- 固定朝向需要精准定位：屏幕准星与实际枪口射线使用共同世界点，并对四角瞄准自动验证。
- 镜头保持可感知的平滑跟随，HUD 显示小幅角度；跟随速度固定，不能扩大转向范围。
- 高分辨率和多个测试浏览器会增加系统负载：渲染有上限，测试串行；实测吞吐只代表对应设备，不承诺所有设备达到 60 FPS。
- 手臂容易被第一人称透视裁掉：桌面截图单独检查枪身、手部与准星的布局。

## 直线追击与拥挤避让（2026-09-04）
